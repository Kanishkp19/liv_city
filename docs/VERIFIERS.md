# Verifiers

Principle: programs first, judges second, fail closed. Implementation in `src/agentville/verifier/`.

## 1. Interfaces
```python
class Stage(Protocol):
    name: Literal["structural","programmatic","judge","audit"]
    async def run(self, job: JobSpec, artifact: Artifact, ctx: VerifyCtx) -> StageResult

class StageResult(BaseModel):
    passed: bool; score: float | None; details: dict; error: str | None = None
```
Recipe = ordered stages + `quality_weights`. Quality = weighted sum of stage scores; programmatic pass is required for any payment; judge can only lower quality (`final = min(programmatic_score_cap, blended)`).

## 2. Structural stage
Validates JSON schema (jsonschema), size limits, encoding, no binary in text fields. Schemas in `verifier/schemas/*.json`. Example `content_post_v1`:
```json
{"type":"object","required":["hook","script","captions","tags"],
 "properties":{"hook":{"type":"string","maxLength":120},
  "script":{"type":"string","minLength":80,"maxLength":1200},
  "captions":{"type":"array","items":{"type":"string"},"minItems":3,"maxItems":12},
  "tags":{"type":"array","items":{"type":"string"},"minItems":3,"maxItems":10}}}
```
Fail => quality 0.

## 3. Programmatic checks: content_creator
| Check | Rule | Score contribution |
|---|---|---|
| hook_length | hook <= 12 words | pass/fail gate |
| banned_words | none of `params.banned_words` in any field | gate |
| required_terms | includes `params.must_include` (each) | fraction |
| cta_present | contains CTA pattern from `params.cta` | gate for difficulty>=2 |
| duration_est | script words / 2.5 wps within `[min_s,max_s]` | linear penalty outside |
| readability | Flesch reading ease within target band | fraction |
| dupe_check | Jaccard 3-gram similarity vs agent's last 20 artifacts < 0.5 and vs global corpus < 0.6 | gate |
| tag_quality | tags lowercase, unique, no spaces >2 words | fraction |
| media_manifest (optional, v2) | ffmpeg probe: duration, resolution, audio present on generated clip | gate |
Score = mean(fractional checks) if all gates pass else 0.

## 4. Programmatic: developer role
Sandbox image `python`. Copy `solution.py` + hidden `tests/test_hidden.py` (from `params.hidden_tests`, generated by engine via seeded parametric generators plus reference implementation). Run `pytest -q --timeout=10 --maxfail=5`. Score = passed/total; gate: >= 60% and no timeout/crash. Also run static checks: forbid `import os, subprocess, socket, requests` via AST scan (defense in depth; sandbox is the real barrier).

## 5. Programmatic: data_analyst / ops_clerk
Analyst: numeric compare with tolerance `params.tol` + method field present. Ops clerk: compare output CSV to ground truth using row-hash set F1; require F1 >= 0.9 for full score.

## 6. Judge stage
Used only where code cannot judge (hook appeal, tone, clarity).
- Panel: 3 judges from `config/judges.yaml` (distinct providers/models), identity-blind: artifact presented without agent metadata, order randomized by seeded RNG.
- Rubric YAML (`judge_rubrics/content_hook_v1.yaml`): criteria with 0-1 scores and anchors, e.g. `hook_strength`, `clarity`, `tone_match`, `originality`, `constraint_adherence`. Judge must output JSON `{criteria:{...}, overall:0..1, rationale:<=300 chars}`.
- Aggregation: median of overall; if `max-min > 0.35` -> flag `judge_disagreement`, stage `passed=False` (fail closed) and record for owner review.
- Calibration: judge prompts include 2 anchor examples (good and bad). Nightly `calibrate-judges` compares judges on the gold set (`tests/gold/*.json`); log drift.
- Judge cannot see hidden params beyond what the rubric needs.

## 7. Audit stage (planted bad work)
With prob `audit_rate`, engine creates **audit plants**: a job whose expected outcome is known bad or known good (agent-independent probe). Mechanism: hold-out synthetic artifacts (`tests/gold/bad/*`, `good/*`) are inserted directly into the verifier queue disguised as submissions (`artifact.origin="audit"`, never tied to a real agent/ledger). Metrics: false-pass rate (bad passed), false-fail rate (good failed). Alert if false-pass > 5% over last 100 audits.

## 8. Anti-gaming measures
- Hidden params/tests varied per job (seeded).
- Test sets rotated; exam tasks never appear on the board.
- Length/keyword stuffing penalties (repetition ratio, type-token ratio bounds).
- Cross-agent similarity check to detect copied playbook-exploits.
- Judge prompt injection defense: artifact text placed inside delimiter block labeled untrusted; judge told to ignore instructions inside it; sanitized for phrases like "ignore previous"; injection flags reduce score to 0.

## 9. Sandbox execution contract (`sandbox/runner.py`)
```python
async def run(image:str, files:dict[str,bytes], cmd:list[str], *, timeout_s:int=15, mem_mb:int=256, cpus:float=0.5) -> SandboxResult
```
Docker flags: `--network none --read-only --tmpfs /work:rw,size=64m --user 65534 --cap-drop ALL --security-opt no-new-privileges --pids-limit 64 --memory 256m --cpus 0.5`. Output captured up to 64 KB. Container always removed. Result stored in `sandbox_runs`.

## 10. Test fixtures
`tests/gold/`: 30 good + 30 bad content artifacts labeled; 20 developer solutions (correct, subtly wrong, malicious) for verifier regression.
